# Pendientes de arquitectura — registro unificado

Registro centralizado de pendientes del corpus por prefijo ([`../../plan-general.md`](../../plan-general.md) §5). Marcadores inline: `**[PENDIENTE X-nn]**` (y análogos P/C/T/R/A en planes de módulo). El detalle amplio (contexto, insumos) sigue en el documento origen; aquí vive el índice de decisión.

**Convención de prefijos:** **X-nn** transversal; **P-nn** Presupuestos; **C-nn** Contabilidad; **T-nn** Tesorería; **R-nn** RRHH; **A-nn** decisiones humanas Adquisiciones.

**Columnas de decisión** (todas las tablas):

- **Prioridad:** triage del registro (no sustituye el grafo del plan-general). Escala: **Bloqueante** (frena F0/F4 o un área entera) · **Alta** (fronteras/bases/contratos críticos) · **Media** (necesario, con default viable) · **Baja** (calibración, tooling, diferible) · **—** (cerrado / absorbido / resuelto).
- **Opciones:** alternativas `(a)/(b)/…` o enums con ` / `.
- **Default propuesto:** valor de trabajo si no hay acta a tiempo. Etiquetar *propuesta de trabajo* cuando no esté asentado en el corpus; *sin default hasta insumo externo* cuando forzar uno inventaría umbral, norma o hecho ajeno al corpus.
- **Criterio de cierre:** quién decide + artefacto que cierra (acta, ADR, ficha, verificación externa, etc.).
- Cerrados / absorbidos / borradores / resueltos se rellenan igual (histórico).

**Cambios julio 2026 (B0):** renumeración arquitectura P→X; **X-47 cerrado**; **X-46 absorbido bajo C-1**; **X-44 reformulado**; **X-77**; **X-82…X-85**; **X-78…X-81**; **X-86…X-93**.

## Glosario — actores de Dependencia externa

Quién debe aportar el cierre (no siempre es el dueño del documento origen). Valores compuestos (`DM / jurídica`) = varias contrapartes.

| Actor | Quién es | Rol típico en el registro |
|---|---|---|
| **ninguna** | Sin dependencia externa de decisión | Cierre interno de arquitectura/especificación |
| **DM** | División de Municipalidades (SUBDERE) | Decisiones de negocio, alcance operativo, ratificación con municipios |
| **jurídica** | Asesoría / área jurídica SUBDERE (o equivalente) | Encuadre legal, normas, convenios, riesgos de bases |
| **jefatura** / **Jefatura SUBDERE** | Dirección del programa / autoridad que fija bases | Alcance de licitación, prioridades institucionales |
| **bases** | Redacción de bases de licitación | Texto contractual exigible al adjudicatario |
| **pilotos** | Municipios piloto del programa | Datos reales, procesos as-is, validación de supuestos |
| **DAF** | Dirección de Administración y Finanzas (municipal) | Controles internos, SoD, operación financiera local |
| **Control** | Unidad de Control (municipal) | Emisión/revisión de informes (p. ej. art. 29 d) LOCM |
| **Finanzas** / **Depto. Finanzas Municipales** | Área finanzas SUBDERE o municipal según contexto | Reglas presupuestarias, Manual de Imputaciones, reportes |
| **Presupuestos / Contabilidad / Tesorería / Adquisiciones / RRHH** | Equipo del módulo SGM indicado | Frontera o contrato entre módulos |
| **plataforma** | Core de plataforma SGM | Auth, tenants, feeds, contratos transversales |
| **arquitectura** | Equipo de arquitectura SGM | Mecanismos transversales, propiedades en bases |
| **SUBDERE** | Institución (cuando no basta DM) | Formatos/canales institucionales (SINIM, CGR, etc.) |
| **CGR** / **Contraloría** | Contraloría General de la República | Formatos de reporte, canales, SIAPER, dictámenes |
| **SIAPER** | Sistema de personal de Contraloría | Interfaz M2M vs portal (R-2) |
| **SII** | Servicio de Impuestos Internos | Cesión de créditos / DTE / registros |
| **ChileCompra** | Dirección de Compras (Mercado Público) | Canal operativo MP (webhook/polling) |
| **Gobierno Digital** | Institución DocDigital / FirmaGob | Verificación de API DocDigital (X-72) |
| **Registro Civil** | Servicio de Registro Civil | Integración RMTNP (T-9) |
| **SGD** | Área / gobernanza de datos o sistemas (nodo SUBDERE) | Criterio PISEE vs canal propio (X-82) |
| **giradores** | Sistemas o unidades que **originan** el cobro y emiten la **orden de ingreso** hacia Caja, sin ser Tesorería SGM | Patentes, permisos de circulación, Juzgado de Policía Local, derechos, SEM u otros; **fuera del alcance de construcción de SGM** (Tesorería D-3). T-1 inventaría cuáles hay y cómo entregan la OI |
| **Camila / equipo** | Personas/equipo nombrados en el documento origen | Levantamientos puntuales (p. ej. inventario nodo) |
| **archivística** | Criterio de retención/archivo | Plazos de auditoría / documental |
| **operación** | Operación sostenida del servicio | Quién opera nodo, DocDigital, etc. |
| **migración** | Trabajo de migración de datos | Series históricas, folios |
| **registro externo** | Registro nacional u otro sistema no municipal | P. ej. deudores de pensiones de alimentos |
| **inventario (X-44)** | Decisión de alcance Bodega/AF | Condiciona dueño de campos de bodega |
| **C-1** | Pendiente de Contabilidad (atomicidad) | Desbloqueo técnico de otro pendiente |
| **técnica + fuente normativa** | Decisión técnica anclada a norma | P. ej. calendario de días hábiles |
